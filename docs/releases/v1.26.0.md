Slides gathered into sections; a message written back to an mbox keeps its
bytes.

## Presentation

- **Home → Section.** The button now opens a menu — Add Section, Rename
  Section…, Remove Section, Remove All Sections — as PowerPoint's does.
  Add Section starts a section at the selected slide and asks for its
  name at once, a "Rename section" dialog prefilled with "Untitled
  Section"; a deck with no sections first gets a "Default Section" for
  the slides before it, as PowerPoint does, since every slide of a
  sectioned deck is in some section, and a slide that already starts a
  section starts it still. Rename Section renames the section the
  current slide is in; Remove Section takes it away and its slides join
  the section before it, the first section's joining the one after; the
  last section standing takes the list with it; Remove All Sections
  takes every section out, the slides staying. Sections are drawn as
  headings above their first slide in the thumbnail strip and in Slide
  Sorter view, the name with the slide count beside it, and a
  double-click on a heading renames it. In the file the sections are
  PowerPoint 2010's `p14:sectionLst` in an extension list on the
  presentation part, written as PowerPoint writes it — one `p:ext` with
  PowerPoint's section-list URI, the p14 namespace on the list, each
  section a name, a GUID and its slide ids; a file with an extension
  list of its own keeps what is in it, and a list PowerPoint wrote is
  read as it comes, its GUIDs kept. Adding, duplicating, moving or
  deleting a slide keeps the sections in step: a new slide joins the
  section of the slide before it, a moved slide belongs to the section
  it lands in, a deleted slide leaves its section, and a section left
  with no slides stays, as PowerPoint keeps one, drawn after the last
  slide so it is not lost. The button was greyed
  out ("Sections are a presentation-part list the engine does not write
  yet").

## Mail

- **A message written back to an mbox keeps its bytes.** Writing an
  mbox went through `TextDecoder('latin1')`, which by the encoding
  standard is Windows-1252: it reads the bytes 0x80–0x9F as the euro
  sign, the curly quotes and their neighbours, whose code points do not
  come back to the byte they were, so an em dash in a UTF-8 message (E2
  80 94) went out as E2 AC 1D and read back as mojibake. The reader and
  the writer now go byte for byte. A Subject line carrying raw UTF-8
  (rather than an encoded word) is now read as UTF-8 when it is valid
  UTF-8.

## Proven, not promised

- Three engine tests in `tests/deck-sections.test.js`: one adds a
  section before a slide, the slides before it falling into a Default
  Section, checks the XML written matches PowerPoint's form
  byte-for-byte at the end of the presentation part, reads it back
  through a save, refuses to double a section a slide already starts,
  splits a section, renames it (trimmed, an XML-hostile name escaped, a
  blank name becoming "Untitled Section"), removes one (folding its
  slides into the section before, or after for the first), removes the
  last one and finds the extLst gone, and removes them all; a second
  inserts, duplicates, moves (down, up, to the very front) and removes
  slides and finds the sections kept in step, an emptied section
  written as `<p14:sldIdLst/>`, and a presentation part with another
  extension already in its extLst keeping it before and after; a third
  reads a list written the way PowerPoint writes it, sets aside a slide
  id not in the show, gives an unlisted slide to the section before it
  on the next edit, keeps PowerPoint's own GUID, and adds a section at
  an unlisted slide. Five window checks in the new `sections` block
  (`RUTBA_VERIFY_ONLY=sections`): Home → Section → Add Section on the
  second slide starts a section there with the first slide in a Default
  Section and the name asked for; the typed name is the heading drawn
  in the strip with the slide count; the saved file carries the list as
  PowerPoint writes it; Remove Section folds it back and Remove All
  Sections takes the list out of the strip and the file; and the window
  reports nothing.
- The engine test "a body with characters outside ASCII survives a
  write and a read" in `tests/mailbox.test.js`, which failed before
  this release, now passes: writing and reading an mbox go byte for
  byte, an em dash and a euro sign in a UTF-8 message coming back as
  themselves.
