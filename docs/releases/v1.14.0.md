Rutba Pictures on a large folder: instant, steady, and drawn only where you look.

## Pictures: a folder of thousands, at the speed of a folder of fifty

The viewer crawled on a big folder with clips among the pictures, and
stuttered as tiles came and went. Four causes, all gone:

- **A tile is a thumbnail now, never the file.** The platform makes a small
  JPEG of each file once — the Windows shell, which knows videos, HEIC and
  whatever else the machine has a codec for — and Rutba Office keeps it on
  disk, keyed by the file's path, size and modification time. The second
  visit to a folder costs a directory read. A folder of five hundred
  photographs no longer decodes five hundred photographs to draw five
  hundred squares.
- **A clip's tile is a frame of it, not a live player.** Every video tile was
  a `<video>` element holding a decoder, and Chromium suspended and resumed
  them as the grid scrolled — the stutter. The platform's frame is used when
  it has one; when it has none (a WebM on Windows without the codec pack,
  anything on Linux) the window draws a frame of the clip itself, one clip
  at a time, and hands it to the platform to keep.
- **Only what you can see is drawn.** The grid and the filmstrip draw the
  rows in view and a little either side; the rest is held as empty room, so
  the scrollbar is the scrollbar of the whole folder and a folder of five
  thousand costs what a folder of fifty costs. Newest requests are answered
  first, so the tiles in front of you arrive before the ones you scrolled past.
- **Moving on never shows an empty frame.** The picture on the stage stays
  until the next one has decoded, and the next two either way are decoded
  before you ask for them. The details panel stays where it is while the
  next file is read, so nothing on screen jumps.

## The folder has the whole window

- With nothing open, the folder fills the window: pictures, clips, sounds,
  PDFs and the folders inside it, each folder a tile you click to enter, and
  **Up** (or Backspace) to come back. One click opens a file; **Escape**, or
  the folder button, goes back to the grid.
- **Chips count the folder by kind** — All, Pictures, Videos, Audio, PDF —
  and pressing one shows only that kind. The order can be by name, newest or
  oldest first, largest first, or by kind. Tiles come in three sizes. All of
  it is remembered on this machine.
- A picture opens on a dark stage whatever the theme, with a filmstrip under
  it and, if you want it, the folder's grid beside it. A zoomed picture is
  dragged about with the mouse.
- A phone's sideways photograph is turned the right way up once, by the
  decoder, rather than by the decoder and then again by the viewer — a
  quarter of everyone's holiday was upside down.
- Trash moves on to the next file rather than back to the grid, so a folder
  can be weeded in one pass.

## Proven, not promised

- Fourteen application checks open a generated folder of three hundred
  pictures, two clips, a sound file, a PDF and a folder inside it, and read
  back what the window did: how many tiles were drawn of how many, that every
  tile is the platform's thumbnail and none a live video, that the frames
  arrive small, that a clip the platform has no thumbnail for gets one drawn
  by the window and kept, the chips, the order, the sizes, the folder inside,
  the sideways photograph turned once, sixteen samples across a Next with a
  decoded picture in every one, and a filmstrip drawn only where it can be
  seen. `RUTBA_VERIFY_ONLY=viewer` runs them alone.
- Eight engine tests hold the viewer's arithmetic — the order, the counts,
  which rows are in view, which neighbours to fetch — and the thumbnail
  cache's key, its newest-first queue, and a frame handed in.

## Under the hood

- `rutba://thumb/<path>?s=256` is a fourth host on the scheme, answered by
  `packages/office-shell/src/electron/thumbs.js`; a window hands a frame in
  through `thumbs.put`, new in the contract.
- The file host now says `Access-Control-Allow-Origin: *`, so a window may
  read back a canvas it drew from a file — the window can already read any
  file through the bridge, so nothing new is allowed.
- The viewer's arithmetic lives in `renderer/apps/pictures/library.js`
  with no window in it; the frame grab in `pictures/frames.js`.
- Pictures opened with a folder's path shows the folder.
