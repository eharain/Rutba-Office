A large workbook scrolls at once, the launcher's recent list scrolls, and an update says so — before, during and after.

## Worksheets: a large workbook scrolls

- **A frame on a sixty-thousand-row sheet is 30 ms**, from a third of a
  second, and 50 ms where the file gave every row a height, from three
  seconds; the first frame after opening is 55 ms, from four. Three things
  paid for it. The frame grew Excel's "current region" round the cursor on
  every scroll step — a walk of every row of the table — and nothing in the
  window read it; it is asked for when wanted. Every row offset walked
  every custom height in the file for every cell of every frame; the
  exceptions are indexed once and an offset is one binary search. And the
  window asked for a frame on every animation frame of a scroll, a dozen
  queued behind the first; one is on its way at a time, and a scroll that
  arrives meanwhile asks once more when it lands.
- **The rows above stay where they are.** Ten rows are drawn beyond the
  edge in both directions — a wheel notch is five — so scrolling up shows
  rows before the next frame lands, and the frame lands before the next
  notch.
- **A hidden row the file also gave a height** took that height in the
  offsets while drawing at none, so every row below it sat too low. It
  takes nothing now.

## The launcher

- **The recent list scrolls.** It was clipped to the room left under the
  tiles: a flex item that hides its overflow shrinks below its content, so
  the last row in reach was cut in half and there was nothing to scroll. It
  takes what is left of the window and scrolls inside it.
- **A right-click on a recent file** offers Open, Show in folder, Remove
  from the list and Clear the list. Enter in the search opens the first
  match.

## An update says so

The suite has found and installed its updates on its own since 1.13 and
said so in a card; the owner's copy still updated in silence, because the
install happens on quit and the next launch looked exactly like the last
one.

- **After:** the first window of a new version says which version it is
  now and which it was, and **What's new** opens the release's own notes —
  bundled with the build, so a copy with the network switched off reads the
  notes the release page carries. OK puts the card away in every window;
  the notes stay under the app menu.
- **During:** every window's status bar counts the download ("Updating
  42%") and says "Update ready" once it is downloaded; the chip brings back
  a card put away with Not now. On Windows the taskbar button shows the
  download's progress.
- **Before:** unchanged. One request to GitHub's release feed every six
  hours, nothing about you or your files, and off means no request at all.

## Proven, not promised

- Four engine tests hold the geometry index (sixty thousand heights, a
  hidden row with a height, the index dropped on a change) and the frame's
  speed on a twenty-thousand-row table; two read the notes into blocks.
- The update block of the application checks drives the states by hand in
  a Rutba Word window and reads the status chip counting, the chip bringing
  a put-away prompt back, the arrival card naming both versions, What's new
  showing the bundled notes, and Close marking the arrival seen through the
  service (`RUTBA_VERIFY_ONLY=update`).

## Under the hood

- `SheetGeometry` keeps its row and column exceptions in tracked
  collections and builds a sorted index with running corrections on first
  use after a change; `viewport()` takes `overscanCols` beside `overscan`.
- `SheetView.regionAround()` replaces the frame's `region`.
- The update service records `updates.lastRun` and `updates.arrived`, and
  the contract gains `update.seen` and `app.removeRecent`; the bundle
  writes `whatsnew.json` from `docs/releases/v<version>.md`.
