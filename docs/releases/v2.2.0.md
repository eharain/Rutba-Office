Rutba Office 2.2.0 moves the suite onto Electron 44 and newer versions of the libraries it is built on, for the browser engine's security fixes and the libraries' own. Nothing you use changes: every app, file and setting works as in 2.1.1, and the whole release routine ran on the new versions before release.

## What moved

- **Electron 43.4.1 to 44.7.2**, the browser engine and runtime every window
  runs in, with its security fixes. Electron 44 rebuilt the clipboard on
  the web's own Clipboard API; copy and paste of words, formatted text and
  pictures go through it now, with nothing changed in how they behave.
- **Mail's libraries**: imapflow 1.7 to 2.4.3, which reads and keeps
  accounts in step over IMAP, and nodemailer 9 to 10.1.1, which sends.
  Both are rewrites with the same calls, so accounts, sign-in kinds and
  sending are unchanged.
- **The build**: esbuild 0.25 to 0.28.2, which bundles the windows; the
  bundle comes out the same size.
- **Smaller updates**: React 19.3.1 and mailparser 3.9.39.
- **The accessibility audit stays at axe-core 4.13.0.** 4.14.0 reads the
  words drawn inside a picture on a button as part of the button's label,
  and finds that Presentations' slide thumbnails and Design gallery
  pictures do not repeat those words in their names. The buttons are as
  they were in 2.1.1. They are being remade so each picture stands beside
  its button rather than inside it, and the audit moves to 4.14 with that
  change. Meanwhile each picture is already kept from screen readers, so
  only the button's name is read.

## How it was proven

Electron 44 changes the clipboard and the runtime beneath every window,
so 2.2.0 carries nothing else, and any fault can be traced to the move. The
gate below ran on Electron 44 with every window check, the clipboard
checks among them. Both fuzzers ran on the new libraries. The installers were
built before the tag, and the installed copy was started from outside
the source folder. After publishing, the upgrade workflow updates 2.1.1 to 2.2.0
installed, portable, and while the app is closing or left open.

The gate now lets the machine settle before the performance budgets. The
engine tests just before them write thousands of files that the virus
scanner goes on reading, and that held the main thread past its budget in
two runs, where the same budgets passed on their own every time. The gate
waits until the processors have been under a quarter busy for three
seconds, up to two minutes, and says how long it waited.

## Gate

Run on Windows (x64) on 2026-10-16, before 2.2.0 was released: 2,689 engine
tests, 2,682 passing and 7 skipped where a package they need is not
installed; 12 of 12 editing checks; 1,961 of 1,961 application checks; and
11 of 11 windows painted clean.
