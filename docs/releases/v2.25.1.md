Rutba Office 2.25.1 fixes a fault in the Locker of 2.25.0. A document opened from the Locker was not seen as open in its Office window when its path had a space in it, which it always has when the Windows user folder has one, such as C:\Users\Sam Khan, and often has when the file's own name does, such as "Staff handbook.docx". Locking then took the document's copy from under its window, and the next Save in that window failed.

This note is also in [Arabic (العربية)](https://github.com/eharain/Rutba-Office/blob/main/docs/releases/v2.25.1.ar.md), [Hindi (हिन्दी)](https://github.com/eharain/Rutba-Office/blob/main/docs/releases/v2.25.1.hi.md) and [Urdu (اردو)](https://github.com/eharain/Rutba-Office/blob/main/docs/releases/v2.25.1.ur.md).

## Locker

- **Lock now with a document open.** With a document from the Locker
  open in Documents, Sheets or Slides, Lock now, the computer locking or
  going to sleep left its folder in place for the window to save into,
  and said the document was still open. With a space in the path it did
  neither: the copy and its folder were removed, nothing was said, and
  the window's next Save said the folder it was going into was not there
  any more. What was saved before the lock was already in the locked
  file; what was typed after it stayed only in the window. The folder
  now stays, the Locker says the document is still open, and what the
  window saves is locked in at the next unlock.
- **Closing the Locker's window.** Closing the window locks the Locker,
  and it waits while a document from it is still open. With a space in
  the path it locked at once. It now waits for the document to close.
- **The idle lock.** The Locker locks after the idle minutes set in its
  settings, and waits while a document from it is open. With a space in
  the path it waited only for the first half minute after the document
  was opened, then locked. It now waits for the document to close.
- **A closed document's copy.** Closing a document opened from the
  Locker clears its copy at once. With a space in the path the copy
  stayed until the Locker was next locked, and until then Rename, Delete
  and, for a file with two versions from the cloud, Delete this version
  each said the file was open. It is now cleared when the document
  closes.

## Checks

Every window check now runs in a profile whose folder has a space in its
name, as a Windows user folder such as C:\Users\Sam Khan gives, so a fault
of this kind shows in any app. The Locker's checks for Lock now, closing
its window and the idle lock each failed on 2.25.0's code before the fix,
and pass with it.
